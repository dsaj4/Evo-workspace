# 数据处理升级设计（bili + weibo + zhihu）

## 1. 目标

当前处理链的优点是简单、稳定、可复现，但信息抽取得还比较浅，核心上仍然停留在：

1. 评论级二分类：是否命中职业不安全感词典。
2. 日度聚合：每天有多少条评论、多少条命中。
3. 事件窗分析：事件前后评论量和命中量是否变化。

这套方法适合做第一版事实基线，但还没有把数据里真正有价值的结构吃干净。当前数据实际上已经包含至少四类可进一步利用的信息：

1. 线程结构：`parent_comment_id` 可区分首层评论和回复，知乎与微博尤其明显。
2. 用户重复发言：三平台都存在重复用户，知乎最明显，可做“持续担忧者”与“一次性围观者”的分层。
3. 源内容归属：B 站 `video_id`、微博 `note_id`、知乎 `content_id` 可用于把评论聚合回“内容单元”。
4. 互动强度：`like_count`、`sub_comment_count` 可用来区分“高传播焦虑”与“低传播自述”。

升级目标不是把方法做得更花，而是从“只知道有没有焦虑”提升到“知道谁在焦虑、在什么情境下焦虑、哪类焦虑传播得更快、哪些事件只是带来围观、哪些事件真的带来结构性担忧”。

## 2. 当前瓶颈

### 2.1 信息损失点

当前词典法把很多不同类型的表达都压成了一个 `has_insecurity`：

1. 个人求职焦虑。
2. 对行业裁员的旁观式评论。
3. 对 AI 替代的预测。
4. 对技能跟不上节奏的自我担忧。
5. 带情绪但没有真实职业风险含义的夸张表达。

这会导致结果“能统计，但不够解释”。

### 2.2 统计单位过于单一

现在几乎所有分析都基于“评论条数”。这会掩盖两个问题：

1. 同一用户高频发言会放大某类声音。
2. 同一热视频/热帖下的密集讨论会被误判成跨平台普遍情绪变化。

### 2.3 平台差异没有被充分利用

从现有数据画像看：

1. B 站体量最大，像“广覆盖舆情场”。
2. 知乎文本更长，像“论证型表达场”。
3. 微博覆盖天数很少，但回复率极高，更像“事件冲击下的即时互动场”。

所以平台不应只作为一个固定效应或分组变量，而应被当成不同的信息生成机制。

## 3. 三种升级路径

### 路径 A：保守增强版

做法：

1. 继续保留词典法。
2. 增加平台标准化、时间补齐、点赞加权、回复/首评区分。
3. 把日度分析扩展为“评论数 + 用户数 + 内容数 + 加权焦虑指数”。

优点：

1. 最稳。
2. 几乎不需要人工标注。
3. 与现有论文最兼容。

缺点：

1. 解释力提升有限。
2. 仍然难区分“情绪性吐槽”和“真实职业风险表达”。

### 路径 B：推荐方案，分层标签 + 多粒度面板

做法：

1. 保留词典法做第一层召回。
2. 在此基础上构建一个小规模人工标注集。
3. 将评论从单一二分类升级为多标签分类。
4. 生成评论、内容、用户、线程、日期五个层级的分析表。

优点：

1. 信息价值提升最大。
2. 仍然在你当前数据和项目规模内可落地。
3. 最适合支撑论文里的“更稳健解释”。

缺点：

1. 需要一次小规模标注。
2. 需要新增几个特征表和校验步骤。

### 路径 C：LLM 主导深度抽取版

做法：

1. 对高价值样本直接做 LLM 分类与摘要。
2. 提取职业、行业、AI 技术类型、因果叙事、政策诉求等复杂标签。
3. 用 LLM 输出构建案例研究和解释章节。

优点：

1. 叙述力最强。
2. 对论文讨论和案例部分很有帮助。

缺点：

1. 成本高。
2. 一致性与复现性较弱。
3. 如果直接作为主分析证据，容易被质疑。

**推荐选择：路径 B。**

原因很简单：它既能显著提升解释力，又不会把论文主证据建立在难复验的 LLM 输出上。

## 4. 推荐的新处理架构

### 4.1 第 1 层：标准化层

先把三平台统一成一张标准评论表 `comment_fact`，至少保留这些字段：

1. `platform`
2. `comment_id`
3. `parent_comment_id`
4. `source_item_id`：统一映射 `video_id / note_id / content_id`
5. `user_id`
6. `timestamp`
7. `date`
8. `content`
9. `like_count`
10. `sub_comment_count`
11. `is_reply`
12. `content_len`

这里最关键的是新增两个统一字段：

1. `source_item_id`
2. `is_reply`

这两个字段会让后面的“内容级”和“线程级”分析真正可做。

### 4.2 第 2 层：多标签语义层

不要再只用 `has_insecurity`。建议把每条命中的评论扩展成以下标签：

1. `risk_target`
   取值建议：`self / occupation / industry / society / unclear`
2. `risk_type`
   取值建议：`job_loss / replacement / skill_obsolescence / hiring_difficulty / wage_pressure / future_uncertainty`
3. `severity`
   取值建议：`low / medium / high`
4. `time_horizon`
   取值建议：`immediate / short_term / long_term / unclear`
5. `stance`
   取值建议：`fear / sarcasm / neutral_observation / advice / resistance`
6. `evidence_mode`
   取值建议：`personal_experience / hearsay / macro_judgment / news_reaction / speculation`

实现方式建议：

1. 词典法先做高召回。
2. 从命中样本和未命中样本中各抽一部分，人工标注 800 到 1,200 条。
3. 用这个标注集训练一个轻量分类器，或者做“词典 + 规则 + LLM 辅助复核”的弱监督系统。

这样你最终不只是知道“焦虑变多了没”，还知道“哪类焦虑在变多”。

### 4.3 第 3 层：结构化聚合层

从 `comment_fact` 往上生成四张新表：

1. `item_day_features`
   含义：每个视频/帖子/回答每天有多少评论、多少不安全感评论、多少独立用户、平均点赞。
2. `user_day_features`
   含义：每个用户每天发了多少条、是否首次表达职业风险、风险类型是否变化。
3. `thread_features`
   含义：每条一级评论下的回复深度、回复量、焦虑扩散比。
4. `platform_day_features`
   含义：每个平台每天的评论量、独立用户数、内容单元数、焦虑比例、加权焦虑指数。

这一步会带来三个非常有价值的新指标：

1. `user_based_insecurity_ratio`
   用“表达过不安全感的用户数 / 活跃用户数”替代单纯评论比例。
2. `item_based_insecurity_ratio`
   用“出现不安全感讨论的内容单元数 / 当日内容单元数”识别事件扩散面。
3. `engagement_weighted_insecurity`
   用点赞和回复加权，识别“传播力高的焦虑表达”。

## 5. 最值得新增的分析问题

### 5.1 事件到底带来了什么

不要再只问“事件后焦虑是否增加”，而要拆成三件事：

1. 事件后，`评论量` 是否增加。
2. 事件后，`表达焦虑的用户数` 是否增加。
3. 事件后，`高严重度焦虑` 是否增加。

这三个问题分开后，你就能区分：

1. 只是流量增加。
2. 只是围观增加。
3. 真正的风险感知增强。

### 5.2 焦虑是集中爆发还是扩散传播

通过线程和内容单元，你可以看：

1. 焦虑是否集中在少数爆款内容。
2. 焦虑是否沿着回复链扩散。
3. 哪个平台更容易出现“首评不焦虑，回复变焦虑”的二次传播。

这比单纯平台均值更有解释力。

### 5.3 谁在持续表达，而不是偶尔说一句

用户级面板可以区分：

1. `首次表达者`
2. `重复表达者`
3. `高频表达者`

这会直接支持一个更稳的解释框架：

1. 如果增长主要来自首次表达者，说明事件在扩散关注面。
2. 如果增长主要来自重复表达者，说明是核心焦虑群体在持续强化表达。

### 5.4 哪类职业风险正在上升

把 `risk_type` 做成时间序列之后，你可以回答：

1. 失业担忧是否在上升。
2. 技能过时是否在上升。
3. 招聘难/岗位收缩是否在特定阶段上升。

这会让讨论章节比现在强很多，因为结论不再只是“有焦虑”，而是“焦虑结构发生了什么变化”。

## 6. 最小可落地实施顺序

### Phase 1：一周内可完成

1. 统一 `source_item_id`
2. 新增 `is_reply`
3. 新增 `content_len`
4. 生成 `platform_day_features`
5. 生成 `item_day_features`
6. 新增三个替代指标：
   `user_based_insecurity_ratio`
   `item_based_insecurity_ratio`
   `engagement_weighted_insecurity`

这一阶段就足够写出明显比现在更有信息量的结果章。

### Phase 2：两周内可完成

1. 抽样标注 800 到 1,200 条评论。
2. 建立多标签分类体系。
3. 训练轻量分类器或弱监督打标器。
4. 输出 `risk_type`、`severity`、`stance` 等字段。

这一阶段会让你从“计数研究”升级成“结构性解释研究”。

### Phase 3：可选增强

1. 事件与内容单元自动链接。
2. 代表性评论自动摘要。
3. 跨平台滞后分析。
4. 案例研究自动化。

这部分适合服务论文的讨论和案例章节，但不建议抢在主分析之前做。

## 7. 质量控制要求

为了让新方法站得住，建议同时加四道约束：

1. 所有高阶标签都必须有人工复核样本。
2. 主结果必须同时报告评论级、用户级、内容级三种口径。
3. 微博单独标注为“低覆盖补充平台”，不与 B 站、知乎同强度解释。
4. 所有解释性结论都要明确是“表达模式变化”，不是直接等同于真实心理水平变化。

## 8. 最终建议

如果目标是“在当前论文周期内，尽快提取更有价值的信息”，最优先做的不是上复杂模型，而是这四件事：

1. 把统计单位从“评论”扩展到“用户”和“内容单元”。
2. 把标签从单一 `has_insecurity` 扩展到 `risk_type + severity + stance`。
3. 把平台差异从“均值比较”扩展到“信息机制比较”。
4. 把事件分析从“量变”扩展到“构成变化”。

一句话概括：

**下一代处理链不该只是统计“焦虑有没有变多”，而要识别“哪类焦虑、由谁表达、在哪类内容中扩散、以什么强度传播”。**
