# 研究方法升级路线图

## 目标定位

本路线图服务于当前论文的“最小稳妥成品化”目标，不追求重开研究，而是在保留现有选题、核心数据和三条主假设主线的前提下，系统升级研究方法链条，使论文在以下四个方面更可辩护：

- 样本构建可解释
- 测量过程可验证
- 议题分析更有理论指向
- 统计推断与证据强度更匹配

推荐执行原则是“先补验证，再加复杂度”。优先提升样本与测量可信度，而不是一开始引入过重模型。

## 推荐路线

### 路线总览

建议采用“平衡升级版”，分为六个阶段：

1. 固定主研究问题与主假设
2. 补做 query 检索与样本构建验证
3. 将词典法升级为“词典 + 人工验证”
4. 在验证基础上升级为“弱监督 + 主动学习”
5. 将议题分析升级为“query 标签 + 主题结构”的双层框架
6. 用更稳的统计模型替代纯比例比较

## 阶段 1：固定主研究问题与主假设

### 建议保留的核心主线

- `H1 平台异质性假设`
- `H2 任务接近性/议题异质性假设`
- `H3 时间动态假设`

### 建议新增的高性价比假设

- `H4 风险类型分化假设`

定义建议：

`不同类型的职业风险表达（如替代焦虑、技能过时、未来担忧）在平台分布和时间变化上存在显著差异。`

该假设的优势在于：

- 不需要推翻现有数据结构
- 直接复用现有五类词典标签
- 能显著增强论文的分析层次

### 不建议恢复的内容

- 不恢复事件主效应为核心假设
- 不恢复恢复时间为主结果
- 不将微博和小红书纳入正式平台推断

## 阶段 2：补做 query 检索与样本构建验证

### 目标

解决当前研究最大的潜在方法漏洞之一：样本是被 query 检索条件筛出来的，但缺乏对检索过滤本身性能的验证。

### 推荐做法

1. 列出当前全部 query 清单，并按平台统计每个 query 的评论数、日期覆盖和命中率。
2. 从“已被 query 抓到的样本”中分层抽样，人工判断其是否属于目标 AI 讨论。
3. 从相邻日期、相邻平台、但未被当前 query 抓到的样本中补抽一批“阴影样本”，检验漏检情况。
4. 报告 query 过滤的：
   - precision
   - recall
   - 误检类型
   - 漏检类型

### 预期产出

- `query_filter_validation.md`
- `query_filter_validation_sample.csv`
- 检索过滤性能摘要表

### 论文落点

方法章应新增一节：

`3.x 检索过滤与样本边界验证`

核心写法应明确：

`本文分析的是被当前 query 体系捕获到的 AI 相关讨论样本，而非平台总体中的全部 AI 讨论。`

## 阶段 3：将词典法升级为“词典 + 人工验证”

### 目标

让“职业不安全感相关表达”不再只是字符串匹配结果，而是一个经过人工校验的代理指标。

### 推荐做法

1. 对现有词典做一次结构化整理，将关键词按以下类别归档：
   - 失业担忧
   - 替代焦虑
   - 技能过时
   - 职业焦虑
   - 未来担忧
2. 为每一类补写操作性定义与正反例。
3. 按 `platform × query × date` 分层抽样人工标注 600 到 1200 条评论。
4. 计算并报告：
   - precision
   - recall
   - F1
   - Cohen's kappa
5. 对误判样本分类，识别以下常见问题：
   - 纯技术讨论误判为风险表达
   - 讽刺/反问造成的假阳性
   - 隐性担忧未被词典覆盖

### 预期产出

- `annotation_guideline.md`
- `gold_validation_sample.csv`
- `dictionary_validation_report.md`

### 论文落点

方法章不再只写“本文采用词典法”，而应写成：

`本文首先采用词典法进行显性表达识别，再通过分层人工标注验证其识别性能。`

## 阶段 4：在验证基础上升级为“弱监督 + 主动学习”

### 目标

在不大幅增加标注成本的前提下，提高识别器对上下文、弱类和难例的处理能力。

### 推荐做法

1. 将词典规则视为 seed labeling rules，而不是最终标签。
2. 使用人工金标准集训练一个轻量分类器，优先考虑：
   - 传统线性模型
   - 中文预训练模型微调
3. 采用主动学习抽取高不确定性样本、边界样本和弱类样本，追加人工标注。
4. 将词典法结果与分类器结果并排比较，保留词典法作为 baseline。

### 推荐执行顺序

1. 先做词典法验证
2. 再做小规模监督分类
3. 最后考虑 LLM 辅助标注

### 关于 LLM 的边界

LLM 适合：

- 预标注
- 边界样本解释
- 标签建议

LLM 不适合：

- 直接替代人工 gold labels
- 在论文中被描述为最终标注真值来源

### 预期产出

- `weak_supervision_experiment.md`
- `active_learning_rounds.csv`
- `classifier_vs_dictionary_report.md`

## 阶段 5：升级议题分析框架

### 目标

把当前“按 query 排名”的分析，升级为更有解释力的议题结构分析。

### 双层框架

第一层：`source_query` 作为外显议题标签  
第二层：在高风险 query 内部识别更细粒度子议题

### 推荐做法

1. 保留当前 query 异质性结果，作为第一层议题分析。
2. 将 query 进一步归入理论驱动的任务接近性分组，例如：
   - 高任务接近性议题
   - 中等任务接近性议题
   - 泛技术讨论议题
3. 在高任务接近性议题内部运行 STM 或其他可解释主题模型。
4. 对主题标签进行人工命名和验证，避免把 topic 直接当成构念。

### 推荐优先级

- 优先：query 分组
- 次优：STM
- 不优先：难解释的黑箱聚类

### 预期产出

- `query_grouping_schema.md`
- `topic_validation_notes.md`
- `task_proximity_mapping.csv`

## 阶段 6：升级统计模型

### 目标

使统计方法与当前数据结构更匹配，不再过度依赖描述性比例比较。

### 推荐升级方向

#### H1 平台异质性

在比例检验基础上，增加一个回归模型：

- logistic regression
- mixed-effects logistic regression

至少控制：

- platform
- query grouping
- date or time index

#### H2 议题异质性

将 query 排名升级为：

- query grouping comparison
- task proximity regression
- platform × query interaction

#### H3 时间动态

时间分析至少补以下两项：

- 周内效应控制
- 评论总量暴露控制

如果曲线明显非线性，再考虑：

- GAM
- spline-based trend model

### 不建议优先做的内容

- 不优先恢复事件主效应
- 不优先做 synthetic control
- 不优先做过重的多层因果设计

## 最小稳妥执行包

如果时间有限，建议只执行以下五项，这五项最能明显提升论文质量：

1. `query` 过滤验证
2. 分层人工金标准集
3. 词典法性能报告
4. 风险类型分化分析
5. query 分组或任务接近性分组

## 建议工作产物清单

在后续清理后的主工作区中，建议只保留以下与成品化强相关的资产：

- 预处理脚本
- 新版假设分析脚本
- 词典与标注说明
- canonical chapters
- formal docx build script
- processed data summary
- final consistency matrix

其他临时测试脚本、旧事件分析脚本和过时草稿建议迁出主工作流。

## 下一步建议

在主工作区清理完成后，按以下顺序继续推进：

1. 建立最小资产目录结构
2. 抽取可复用词典与 query 清单
3. 规划人工验证样本
4. 先完成“最小稳妥成品化”
5. 再决定是否追加弱监督与 STM 升级
